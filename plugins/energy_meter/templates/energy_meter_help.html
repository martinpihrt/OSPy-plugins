$_(u'Energy Meter help')
$_(u'Overview') $_(u'Settings')

$_(u'Connection')

$_(u'Use Direct LAN / IP whenever possible. Enter an IPv4 or IPv6 address, optional port, or a DNS name resolvable by the OSPy computer. The plug-in reads Shelly.GetStatus locally and does not require Internet access. Shelly local authentication uses the configured user and password.')

$_(u'Shelly Cloud Integration is an alternative source. It only works when that plug-in is installed, enabled, configured and already exposes the selected three-phase meter.')

$_(u'After OSPy or Shelly Cloud Integration starts, Energy Meter recognizes a configured meter that is still waiting for its first cached reading. Only that meter is retried every five seconds without recording a failure traceback or changing the configured sampling interval for other meters.')

$_(u'Meter roles and solar systems')

$_(u'Grid connection records energy imported from and exported to the public grid. Solar production records generated energy. Load records a separate consumer and Auxiliary is an independent meter. Grid export is never presented as solar production. With both Grid and Solar meters, house consumption equals production plus grid import minus grid export; self-consumption equals production minus grid export. Battery charging and discharging are not inferred without a dedicated meter.')

$_(u'Phase-by-phase accounting adds import and export from every phase separately. Net / vector sum accounting compensates simultaneous phase import and export inside every sampling interval, then records only the remaining import or export as the accounted total. This matches grid meters that settle the vector sum of all phases. It is not a net calculation over the complete day: import and export in different intervals remain separate. Per-phase history always retains the raw Shelly counter differences for diagnostics. Shorter sampling intervals follow rapid direction changes more closely, while producing more history records.')

$_(u'History and counter replacement')

$_(u'Current Shelly cumulative counters and the previous sample are persisted atomically. OSPy therefore continues after restart without losing the counter baseline. If a counter decreases, the plug-in records a reset and establishes a new baseline without adding a false energy spike. Use Reset baseline before replacing or resetting a meter.')

$_(u'Each completed sampling interval stores raw import and export energy plus power for L1, L2 and L3, the configured accounting mode and the accounted totals. The default interval is 60 seconds. Changing the accounting mode affects only new intervals and does not reinterpret retained history. Local history is appended to a journal so the complete history file is not rewritten every minute.')

$_(u'Overview totals and selected-day results are calculated from the retained interval history. Delete history therefore clears these overview values as well. Only the current cumulative-counter baselines are preserved, solely so the next sample continues from the current meter values without adding a false energy spike. Deleted historical totals cannot be reconstructed from the preserved baselines.')

$_(u'Calendar periods')

$_(u'Use the calendar-day selector on the overview to inspect any retained past day. Today, yesterday and every selected day follow the local date and time configured on the OSPy server: a day starts at 00:00 inclusive and ends at the next 00:00 exclusive. The physical Shelly cumulative counters are not reset at midnight; the plug-in splits and sums recorded intervals at calendar boundaries.')

$_(u'Prices, storage and mobile data')

$_(u'Applied import and feed-in prices, currency, cost and income are stored permanently with each interval in local and SQL history and CSV export. Equal tariff start and end times mean the complete selected day. If an interval crosses a tariff boundary, its price is calculated as a time-weighted combination of the applicable tariff segments. The history table shows the stored tariff, currency and both applied prices, while the overview displays the resulting cost and feed-in income for the selected day, yesterday, the current month and the current year. Later tariff changes do not recalculate historical prices or totals. Overview monetary totals include only records in the currently configured currency because currencies are not converted or added together.')

$_(u'History can be kept in local JSON, SQL through Database Connector, or both. The OSPy mobile API receives live meter power, period totals and bounded history.')
